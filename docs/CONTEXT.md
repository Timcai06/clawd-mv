# 背景和决策记录

这个项目在 2026-09-30 的一次会话里立项（那次会话开在 `~/DEV/TTT I'M`）。之后的工作全部在本目录进行，所以当时的上下文都记在这里。决策改了，就更新这份文档。

## 起点
- Tim 想从做音乐开始，完整做一支视频：Claude 的形象 Clawd（橙色像素小螃蟹）在 VS Code 里写代码。
- 参考是 [mexicat/pdoom-video](https://github.com/mexicat/pdoom-video)，YouTube 上有 4K 成片：https://www.youtube.com/watch?v=5EoO5413dBY 。

## 对参考的理解（为什么用这个底子）
- 它不是 AI 视频，也不是用剪辑软件做的，而是 three.js 网页程序：每一帧只由歌曲时间决定，预览和导出的成片完全一致。作者说这个项目是和 Claude Opus 5.5 在 Claude Code 里一起做出来的。
- 流程分四层：歌（上游用的是别人的歌）→ 分析（Demucs 分离人声、逐词对齐、拍点和段落）→ 剪辑表（场景切换点 = 「某句歌词第一个词之前的最近一拍」，不写死时间）→ 场景加离线渲染（无界面 Chrome 逐帧出图，再交给 ffmpeg）。
- **最值得学的一点：歌词就是分镜。** 每句歌词都有专属的画面创意，并且逐词同步。
- 上游规模：约 2.1 万行代码、17 个场景、改到第 5 版，4K 在 M5 Pro 上渲染了 2.5 小时。
- 它的风格规范**明确禁止吉祥物和可爱风**（冷幽默、版画风），和我们的方向相反。所以只借引擎和流程，风格规范我们自己写。

## Tim 的偏好（从其他项目的经验里摘来的，和本项目相关）
- **视觉和听感都由 Tim 验收。** Claude 和 Codex 不截屏、不录屏自查，不对画面和声音下审美结论，只报告测量数据。
- **创意类工作要大胆，不要占位和温吞的小修小补。** 可以提议推倒重来。交付物必须是能看的成片或静帧，文字描述不算。
- **前车之鉴（Context 短片，2026-09-29 至 30）：** 用了 Remotion + gpt-image-2 + Blender 三套工具，花了好几天做 30 秒的写实静物片，Tim 的评价是「效果一般般」，而且不适合做自媒体。教训是：**优先迭代速度和故事，而不是渲染的真实感。** 本项目用单一代码引擎、由歌驱动，正是针对这一点。
- **审美上的一个提醒：** 2026-09-28 Tim 评价作品集动效片「太像素风、全黑背景很无聊」。Clawd 本身是像素造型，改不了。但周围的世界（编辑器、背景、光）**不要默认做成像素风加死黑底**。上游 pdoom 的配色恰好是近黑底，阶段 4 要专门讨论这一点。
- **2026-09-30 Tim 看第一轮设计图（纸面日光、糖果色块、一天的色彩弧线）：「有点太偏卡通了」。** 方向往成熟、克制走：不要描边、贴纸、夸张造型；Clawd 本身是像素卡通，周围的世界不要跟着卡通化。
- 设计方法：做减法，去掉 AI 味（多余的辉光、渐变、装饰性容器）；约束要写得具体、有野心；参考只当基准线，不照抄。
