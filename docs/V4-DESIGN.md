# v4 设计宣言

> C（Opus）2026-10-01 写，等 Tim 看。依据：pdoom 场景源码（loss、stack、hook、loom、prompt、outro、dense、spacetime 等）、整片预览 v3、`data/lyrics.json` 的逐词时间。
> 这份文档取代视觉规范 v2、歌词 v3 定稿、分镜图 v2 作为 v4 的主文档；那些文档降为参考。

## 0. 一句话

**整片是一次连续的下潜：Clawd 的光标从一声 ping 出发，穿过日历、代码、键盘、玻璃、雨、调用栈，一路钻到第 42 行，剪掉一条线，再从一台机器拉远到所有机器。** 每一场都是「一张界面或一组数据，在一个连续镜头里变成一个世界」，歌词骑在这个世界的几何上。

## 1. v3 的问题（事实，不是审美结论）

按 2 秒一帧拼的 80 张静帧（`out/preview/clawd-mv-preview-v3.mp4`）看：

- **它是一叠海报，不是一个世界。** 80 个镜头平均 2 秒，大多数镜头是正对镜头的平面构图（超大字 + 一个面板），镜头之间靠硬切和颜色切换衔接。pdoom 22 个条目，一个条目平均 7 秒，每个条目内部是一个连续的、会动的镜头。
- **3D 空间只在少数几场出现**（S04 日历块、S07 键盘、S14 栈、S15 ≤）。其余场景镜头基本不动。
- **歌词大多「放在」画面上**（左上角或居中），不是「长在」几何上。loss 里的字是贴着曲线走、站在峡谷底、随坠落拉开的。
- **场景之间没有接力物**。S10 的 19 块红玻璃和 S16 的 19 根绿柱是两套东西；S04 的第 32 天到 S15 剪线时没有回来。故事里本来就有的伏笔没用上。
- 尾奏 29 秒（131.9–160.6）几乎是一张静帧：星座、两张日历、日出。
- 代码量：我们 18 场共约 5.9k 行，pdoom 17 场约 19.6k 行。差距主要在每场内部的阶段数和镜头设计。

## 2. 从 pdoom 源码学到的 8 条方法

读的是代码本身，每条都对应具体实现：

1. **一个坐标系贯穿变形。** loss 的图表 y 轴是对数 loss，地形高度用同一个 `DEC`（每个数量级 2.2 个世界单位），所以等高线的数值就是图表刻度的延续。图表不是「切换」到地形，而是同一个数据从 2D 走进 3D。
2. **镜头是 t 的函数，分阶段，阶段边界挂在词和拍上。** `camera(t)` 按 `tDrop / tIn / tCut1 / tCut2 / tRoll` 分 5 段，每段的起止用 `pick()` 找最近的拍。阶段内是连续运动，阶段之间允许「镜头内的硬切」（重新构图），但世界不换。
3. **物理让节奏可信。** 火花从悬崖掉下去用真实的匀加速，`gFall` 是反算出来的，保证正好在唱「in」的那一刻落地；落地给一个冲击波纹（`uRipT`）和一次震屏。
4. **歌词有轨道。** 每个字有自己的出现时刻（按词内字符插值），沿路径排布、按透视缩放、刚写出来是白热色然后冷却（`heatCss`）。「drop」四个字母竖着往悬崖下排，越往下越大。
5. **唯一的亮色是叙事主角。** 火花是 loss 里唯一的橙色；它画曲线、它坠落、它沿峡谷下降。镜头跟它。
6. **冷幽默的注释。** `grokking (?)`、`Δloss −99.9999%`、`sharp minimum (generalizes poorly)`，等高线标高标签，`local min.`。画面像一张会动的科学插图。
7. **张力在切点前堆起来。** loss 最后 0.5 秒：横滚 180°、色散 1.2→4.7、暗角加重、每拍一次 zoom punch、等高线脉冲从八分音符加速到十六分音符，然后硬切。
8. **出口几何就是下一场的入口。** hook 的每次退场都把一个具体形状（火花、眼睑缝、一根线）交给下一场，位置和尺寸是常量；outro 甚至倒放全片、停在第一帧，首尾闭环。

## 3. 视觉语言

### 3.1 世界观：代码是物质
- 片中所有「东西」都由字符构成，或者能还原成字符：地形是代码行，雨是堆栈信息，星空是机器，玻璃碎片上还印着测试名。**任何一个物件拉近都能看到它是字，任何一行字拉远都能变成物件。** 这是全片的魔术。
- 技术底座是一个新的公共部件 **`kit/glyphs.ts`：GPU 字形场**。用 IBM Plex Mono 和 Archivo 生成 SDF 字形图集，一次画 10 万个以上的字，每个字的位置、朝向、大小、颜色在顶点着色器里由 t 算出。代码地形、按键字流、堆栈雨、机器阵列都用它。

### 3.2 三个主角，一个笔头
- **Clawd**：官方 16×5 像素形象不变。每场有明确的动作（敲键、跳、掉、抬头、睡）。
- **光标**（clay 块光标）是我们的「火花」：它写字、它领路、镜头跟着它。片中唯一会发光的 clay 点。Clawd 和光标始终在同一个画面里，光标是 Clawd 的笔。
- **歌词**：每一场都给歌词一条**轨道**（曲线、地面、玻璃、雨线、栈帧、代码行），字长在轨道上，按逐词时间写出，刚写出时发热、随后冷却。

### 3.3 颜色：给三种底色叙事意义（v2 是按场轮换）
| 底色 | 含义 | 出现的地方 |
|---|---|---|
| INK（墨蓝夜） | 机器内部：代码、测试、调试 | 主歌、预副歌、breakdown、bridge |
| CLAY（陶土橙场） | 副歌：COMMIT 冲击 | 三遍副歌的主题词时刻 |
| PAPER（纸，日光） | 机器外面、人类的世界：PR 审查、合并、第二天 | 绿灯之后逐渐亮起，尾奏天亮 |

- 光线随剧情走：9 点开局是夜，越往下潜越暗（call stack 最暗），剪掉那条线之后开始亮，19 个绿灯把画面点亮，合并后天亮。**全片是一条从夜到早晨的亮度弧线。**
- 红和绿只用在测试状态和 diff 上（沿用决策）。v4 放开一条：绿可以在「Nineteen green」发光，它是全片的回报色。

### 3.4 镜头
- 每场一个连续的世界；场内按词和拍分阶段（pdoom loss 的写法），阶段之间可以重新构图，但不换世界。
- 运动有物理：坠落用匀加速、落点有冲击、停止用弹簧（S14 已经这么做）。
- 切点前堆张力（色散、暗角、zoom punch 逐拍加密），然后在拍上硬切。

### 3.5 字
- 唱的词：连续 Archivo（`kit/vartype.ts`），长音拉宽、重音加粗（`kit/lyric-moves.ts` 的 Voice 继续用）。
- 机器的字：IBM Plex Mono。注释、标签、状态栏、测试名都用它。
- 冷幽默注释作为固定手法，每场至少一处，例如 `days.length === 32 // expected 31`、`retry 3/3`、`cache: 0 B`、`Δ −1 char`。

### 3.6 贯穿全片的仪表：状态栏
借 pdoom 的 P(doom) 读数：屏幕底边一条极细的编辑器状态栏，全片常驻（各场可以把它吸进画面或盖住）：
`Ln 1, Col 1 · tests 0/19 · 09:00 · main`
- **Ln** 是全片的「高度计」：开场在第 1 行，一路往下，call stack 下坠时快速滚动，停在 **Ln 42**。
- **tests** 从 0/19 → 19 个红 → 19 个绿。
- **时间**从 09:00 走到第二天早上（尾奏）。
- **分支**从 `fix/october-32` 合并回 `main`。

## 4. 场次重组：18 场 80 个镜头 → 13 个连续场（plate）

一个 plate 对应一个时间线条目，内部自己分阶段（pdoom 的写法）。切点照旧由词和拍算出，不写死秒数。旧的 `shots.json` 保留作参考；新增 `storyboard/plates.json`，`timeline.ts` 改读它。

## 6. 连续性

- **一个笔头**：光标从第一帧亮到最后一帧，每一场都由它开始或结束。
- **一组伏笔**：第 32 天（P2 悬在网格外 → P10 跟着那一横掉下去 → P13 日历翻到 Nov 1）；19 块玻璃（P5 碎 → P6 变雨 → P11 倒飞回来变绿）；git 主干（P4 → P8 打结 → P12 合并成地平线）；「my machine」的那台笔记本（P4 结尾 → P12 拉远的起点 → P13 Clawd 睡在它前面）。
- **一个读数**：底部状态栏的 Ln / tests / 时间 / 分支，全片连续变化。
- **一条亮度弧线**：夜 → 更深 → 第 42 行 → 绿光 → 日光 → 天亮。
- **交接是几何常量**：每个 plate 的出口形状、屏幕位置、尺寸写进 `kit/handoff.ts`，下一场的第一帧从这里接（沿用已有做法）。

## 7. 技术

新增的公共部件：
| 部件 | 内容 | 用在 |
|---|---|---|
