# 分镜表

> 状态：第二版（2026-09-30，C 写）。Tim 看了第一版，认为 8 个场景太少，做出来会和想象差很多，所以扩到 18 个场景、80 个镜头，平均每 1–2 小节一个镜头。
>
> - **数据源是 `storyboard/shots.json`**。本文下半部分的逐镜头表由 `python3 tools/storyboard_md.py` 从它生成，不要手改表格，改 JSON 后重新生成。
> - 这份 JSON 会被引擎读取，渲染成跟着真歌播放的**灰盒动态分镜**（任务 X4）。这样 Tim 看的是会动的分镜，不只是文字。
> - 世界观和配色还没定（设计图在 `out/design/`），这里只写**内容、动作和剪辑**，不写颜色。
> - 画面只由歌曲时间 t 决定。镜头切换**锚定在歌词的某个词上**，再吸附到拍点。表里的秒数是 Whisper 在定稿 WAV 上测的近似值，只作参考和兜底；阶段 3 的逐词对齐数据出来后，时间自动变准，分镜不用改。

**几条贯穿全片的线**，是为了让 2:40 不散：
- **四次「刹车 → 落拍」**：S08 两次、S13 两次、S17 一次。构图相同，每次落拍弹出的东西都升级：哈希 → 两行哈希 → git log → 挤爆屏幕 → 金色哈希。

- **首尾呼应**：S01 的欢迎框和光标 ↔ S18 回到同一个构图，最后又弹出一个新 issue。

## Clawd 动作库（初版，编号供分镜引用）
Clawd 是 16×5 的像素精灵（`reference/clawd/clawd.json`，以终端欢迎界面为准）。所有动作都在这个网格上完成，不加细节、不改比例。只能改变像素的位置（移动、上下弹跳），或者改变眼睛和手臂那几个像素。

| 编号 | 动作 | 像素上怎么做 |
|---|---|---|
| A1 | 睡 | 眼睛那两格填成身体色（闭眼），整体每 2 拍下沉 1 像素（呼吸） |
| A2 | 醒 | 先睁一只眼，再睁另一只 |
| A3 | 待机 | 每拍弹一下（上移 1 像素再落下） |
| A4 | 打字 | 四条腿轮流抬起，每 1/8 拍换一条；手臂一上一下 |
| A5 | 横着走 | 整体水平移动，腿两两交替 |
| A6 | 跳 | 在锚点上跳起，下一个强拍落地；落地那一帧身体压扁 1 行 |
| A7 | 举手 | 两侧手臂那两格上移一行（挡雨，或欢呼） |
| A8 | 慌 | 水平抖动 ±1 像素，频率 1/16 拍 |
| A9 | 数数 | 腿一条条抬起（1、2、3、4），抬完再从头数 |
| A10 | 剪 | 一侧手臂伸长若干像素，再收回 |
| A11 | 下沉 | 缓慢往下移，眼睛朝下（眼睛像素下移一行） |
| A12 | 庆祝 | 连跳，每拍一次，手臂举起 |
| A13 | 挥手 | 一侧手臂上下动 |
