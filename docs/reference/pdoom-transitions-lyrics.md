# pdoom 的交接与歌词（源码研究）+ 我们 18 场的对照

C 2026-10-03 写（阶段 8 第 1 步）。依据：`reference/pdoom/scenes/*.ts`、`reference/pdoom/app-timeline.ts`、pdoom 的歌词和拍点数据；我们这边依据源码和 v5 实测帧（`out/wip/v6-cuts/sheet0–2.png`：17 个切点各取「切前 0.5 s / 切前最后一帧 / 切后第一帧」；`out/wip/v6-mid/sheet.png`：每场一帧；`out/wip/v6-commit/sheet.png`：5 次 COMMIT 重音前后）。只写技术事实和设计意图，好不好由 Tim 判断。

## 0. 结论先行（按影响排序）

1. **切点位置是我们衔接差的第一原因。** pdoom 21 个切点全部用 `cut(q)` = 「该句第一个词之前（含）的最后一拍」，所以切点永远落在两句之间；跨切点的只有上一句**最后一个长音的尾巴**（0.04–0.42 s），而且由下一场在**完全相同的屏幕版面**里唱完（shoggoth 接 room 的 `shrooms`）。我们 17 个切点里 **13 个落在句中**：7 个切在句子中间、后半句的整串词都在下一场（S02 `ping|on my screen`、S03 `bug|report…`、S04、S05、S06、S07、S16，尾巴 1.1–3.5 s）；另 6 个是长音尾巴（S09、S10、S11、S12、S14、S18），但下一场**把整句从头重新排一遍**，位置、字号、字体都变了（实测帧里 S09、S10、S11、S12、S18 第一帧都重写了整句）。观众看到的就是「同一句歌词跳了一下」。
2. **交接常量在 v5 改成 3D 后有几处失效。** 实测：S07→S08 光标从屏幕中央跳到左上角；S15→S16 剪下的横杠在 x≈1010，S16 第一块骨牌在 x≈200；S12→S13 的 clay「11」没有长成 S13 的 clay 半屏（第一帧只剩右下角一小块）；S13→S14 git log 上滚和栈井下坠在画面上没有关系。对得上的：S03→S04 迷你日历、S09→S10 的 19、S11→S12 方框行、S14→S15 发光线、S16→S17 骨牌面（大致）。
3. **pdoom 的交接物几乎都是「收成一个几何原语，再从原语展开」**：点（hook1 的火花、ilya 收成画面正中的点）、线（shoggoth 的 flatline、hook4 的纬线）、缝（hook2 的眼睑缝）、轮廓（hook1 留下的 P(DOOM) 描边被 room 打碎）。我们的交接物多数是「一个矩形对上另一个矩形」，而且常常只在最后一帧对齐，没有收束的过程。
4. **歌词载体：pdoom 每一句都长在该场的世界上**（曲线、峡谷中心线、翻牌板、生物体的雕刻、黑洞透镜、导火索、吉他弦、token 树、[MASK] 块、栈块平面）。我们 18 场里只有 4 场的歌词贴在世界上（S07 键帽 `Plate`、S10 玻璃上的字条、S14 `WordPlane`、S15 ≤ 的面 `planeAffine`），其余是正对镜头的平面排版（`drawSet` / `gridSnap` / `fillRun`）。
5. **同步粒度：pdoom 逐字母**（字母 j 的出现时刻 = `lerp(word.start, word.end, j/len)`，长音只铺前 80%，且不早于书写头/火花到达），**我们逐词**（`Voice` 让整个词在词首一次出现）。冷却色（`exp(-age/0.28)` 白热→ember→bone）我们已有（`heatColor`）。
6. **书写头 = 火花 = 卡拉 OK 光标**：loss 的火花 x 就是已唱字符的位置（`sparkX` 用 `wordProgress` 算），shoggoth 的 X 光扫描带前沿、fuse 的燃烧点、loom 的树梢、leftturn 画路标的火花，都是「正在唱到哪里」。我们的 clay 光标在 S10、S11、S12 完全不出现，其余场多是装饰，不是书写头。
7. **三次 COMMIT 几乎是同一张画**：S08、S13、S17 的 MIT 冲击都是「一个 COMMIT 横贯满屏、clay 底」（S13 加了透视），没有逐次升级。pdoom 的四次 hook 换底色、换尺度、换节奏、换退场方式，而且第 3 次故意掉到最小（breakdown），第 4 次才最大。

## 1. pdoom 的交接

### 1.1 切点怎么选（`app-timeline.ts`）
- `cut(q, nth, tol=0.02)`：句子第一个词起点 + 0.02 s 之前的最后一拍。全片 20 个 `cut` + `open` 从 0 开始 + `outro` 用音乐分析的段落起点。只有一处调容差：`dense` 用 0.05，注释「'Post' 比拍早 32 ms，别把 disobey 切成两半」——**宁可调切点也不切断词**。
- 切点挂在拍上，不强求小节第一拍。场景内部的「硬切重构图」才挑小节第一拍（loss 的 `tCut2`、shoggoth 的 `tCut2`、room 的 `tB`）。
- 实测（pdoom 自己的数据）：跨切点的只有上一句最后一个长音，尾巴 0.04–0.42 s。

### 1.3 切点前的张力
- **细分加速**：room 的分叉 8 分音符翻倍，到 FOOM 改 16 分（1→1024）；loss 的震屏翻转时 8 分、最后一拍 16 分；shoggoth 闭眼序列加速，最后一下压在塌缩拍上。
- **最后 0.1 s 定住**：hook 退场前 `shake=0, zoom=1, ca=0.5`（注释：「退场要把几何交给下一场：让画面定住」）。
- **增益爬升**：交接物最后几十毫秒变白热（hook1 `gain` 到 1.9，hook4 到 2.2）。
- **吸气**：fuse 最后半拍「吸气」再切；loss 末段 fov 34→64 俯冲进极小值。
- **刹在切点上**：loom 的俯冲、paperclips 的天花板逐拍压下直到缝只剩一条线。

### 1.4 火花接力（pdoom 唯一的橙色主体）
open 的笔（火花）画完独角兽，滑到 loss 曲线的起点 → loss 火花画曲线、掉下悬崖、沿峡谷走进极小值 → hook1 的火花在 room 的根上 → room 的火花逐拍分叉 → spacetime 的扫描束、从井里冒出来画回形针 → paperclips 的线弯成回形针 → fuse 的导火索 → stack、loom 的纬线和树梢 → ilya 的点 → outro 引爆。**它在每场里既是书写头，又是交接物。**

## 2. pdoom 的歌词

### 2.1 底层做法（全片共用）
- 逐字母时刻：`t_j = lerp(word.start, word.end, j/len)`；长音只铺前 80%（spacetime 的环形词）或最多 0.7 s（`begun`）。
- 不早于书写头：loss `glyphTime = max(t_j, 火花到达该字的时刻)`。
- 出现：纵向从 0.3 弹到 1（`outBack`，0.16 s）；或从板面抬起 0.45 落下、放大 1.7→1（room，`outExpo` 0.12 s）。
- 冷却：`heat = exp(-(t-t_j)/0.28)`，白热→ember→bone；在 3D 地形上加 16 px 的 ink 描边隔开背景（loss 峡谷字）。
- 长音 = 形变：LIES 每拍换一档宽度；BOSS 宽度 62→125、字号 120→270；FOOM 每个 16 分音符换宽度；blues 按真实音高弯弦；dense 每个底鼓压一次（宽 125→62、重 300→900、字距变负）。

### 2.2 每场的载体
| 场 | 载体 | 逐字机制 / 随世界怎么动 |
|---|---|---|
| loss | 图表曲线 → 3D 峡谷中心线 | 字骑在曲线的平滑趋势上（在尖峰上方加一个小丘，让 sudden 整词拱过去），角度 = 0.6×切线；峡谷字按弧长放在 3D 中心线上，宽度 = 相邻两点投影后的屏幕距离（透视压缩），高度 = 透视尺度，角度跟切线（夹在 ±0.7）。**drop**：四个字母竖着沿悬崖往下排，每个字母的位置 = 火花在那个字母时刻的下落位置，越往下越大。servant/boss：层级反转，BOSS 在滚转的画面里倒着排，随 180° 翻转变正 |
| stack | 每个变换器块里的 `TextPlane`（字的贴图平面，着色器里做卡拉 OK：prog、dir、feather、未唱/已唱/唱完三色） | 镜头每拍落一块，一块一个词；disobey 每个字母一个平面，从右往左亮，每亮一个就脱队 |
| room | 吊在桌上的翻牌板，逐字母 `planeAffine` 盖章 | 每个盖章让板在轴上抖一下（阻尼正弦）、飞出热碎屑；军鼓上整块板翻面（`springStep`），背面是下一句；SHROOMS 撕下来飞向镜头 |
| shoggoth | 刻进生物体雕刻里的字（着色器在字的平面上切排线，触手从前面穿过） | X 光扫描带的前沿就是卡拉 OK 光标；LIES 每拍换一档宽度；SHINIGAMI 每个音节一根引线咬住一只眼 |
| spacetime | 示波器扫描束写字 → 被黑洞真实透镜弯曲（含内圈翻转的虚像） | NOW 的 O 就是黑洞；环上字母按唱铺开；begun 在洞下弯曲 |
| fuse | 导火索 / 回归线 | 每个词唱到就点燃、发光、烧成灰掉落；blues 站在弦上，弦按真实音高（pYIN 数据）弯，松开会颤 |
| dense | 安全框里的字板 / GPU 格子 / 倾斜的桌面 | 逐底鼓压缩到实心，再在重读词上依次冲破安全框、动作框、画框；格子拼字；ASKEW 每拍更斜 |
| loom | token 树 / [MASK] 块 / Droste 递归 | 火花沿路径逐 token 写出唱到的词，其余候选带概率向上下分叉；[MASK] 按词揭开；递归里这句保持清晰 |
| prompt | 提示框里的 token | token 在唱词起点准确出现，上方闪一个下一个 token 的概率分布；⏎ 发射副歌 |
| bureau / leftturn | 表格字段 / 路面标线、甘特条 | 打字机打进字段，`backward` 镜像，`repeat` 把最后一拍按重映射时间重渲 3 次；火花边跑边刷路标；甘特条按唱填满 |
| hook | 全屏一个词 | 见 2.3 |

### 2.3 hook 四次怎么升级
| | 底色 | 词 | 节奏 | 冲击 | 退场 |
|---|---|---|---|---|---|
| 1 | bone 字、ink 底，干净 | 每词一次全屏砸（slam 0.16），字体标本参考线（基线、大写高） | 每词一次 | 震 7 px/词，DOOM 10 | 收成火花 → 居中 P(DOOM) 描边 → room 打碎 |
| 2 | 反转：ink 字、signal 满屏 | 同上，数字提前在「P(」进场 | 同上 | 震 13 | 色场合成眼睑缝 → ascent |
| 3 | 掉到最小：细线、54 px、大片黑 | 前面的词往上漂走变淡；背后有数字的幽灵 | 无冲击帧 | 不震 | 一根根灯丝熄灭 |
| 4 | 最大：底色 8 分音符频闪 ink/signal/bone | 每拍重砸（`retrig`）、slam 0.3、6 层描边回声；UPPING 每个 8 分音符发射一份 | 每拍 | 震 20/26 | 9 越来越多变成线 → loom 纬线 |
另外每次砸都有 2 帧反色（第 3 次没有），按住的词以每秒 3.5% 的速度慢慢逼近镜头。**升级不是单调的**：2 反转，3 掉谷底，4 才是峰。

### 2.4 规律
1. 每一句都有只属于它的载体，载体来自那一场的世界，字跟着世界运动（翻面、透镜、烧掉、弯弦、坠落）。
2. 书写头 = 火花 = 卡拉 OK 光标。
3. 逐字母出现、白热冷却；长音必变形。
4. 语义动作：反转层级、镜像、口吃重渲、反向高亮、倾斜。
5. 字有寿命：出现 → 白热 → 冷却 → 随世界离开（碎、烧、翻走、留在后面），不会原地淡出。

## 4. v6 交接与歌词的规则（设计提案，等 Tim 看）

**R1 切点规则**：默认照 pdoom，切在句首词之前的最后一拍。例外只有一种：被唱到的词本身就是下一场的开场冲击（只留 S01→S02 的 ping），这时前半句用共享版面跨切点保持不动。需要改 `storyboard/shots.json` 的 6 个切点（数值是按 pdoom 的 `cut()` 在我们数据上算的）：

| 切点 | 现在 | 改为 | 前移 |
|---|---:|---:|---:|
| S02→S03（Got a bug） | 7.413 | 6.512 | 0.90 s |
| S03→S04（There’s a thirty-second） | 11.016 | 10.566 | 0.45 s |
| S04→S05（So I crack） | 14.621 | 13.720 | 0.90 s |
| S05→S06（Read the code） | 18.210 | 17.764 | 0.45 s |
| S06→S07（Claws on the keys） | 21.803 | 20.901 | 0.90 s |
| S15→S16（One goes green） | 107.334 | 106.891 | 0.44 s |
（S02 会从 1.8 s 缩到约 0.9 s，正好是一次 PING 冲击的长度。）
（落地时容差取 pdoom dense 的 50 ms：0.02 s 会把上一句的最后一个词 seen、over 切到下一场，所以这两个切点落在句首词后 26 ms / 22 ms 的那一拍。）

**R2 长音尾巴**：下一场只把那一个词在上一场的屏幕版面里唱完，然后由自己的世界处理掉（打碎、落下、被盖住）；**禁止重排整句**。`kit/handoff.ts` 从常量升级为函数（照 `room-shrooms.ts`）：导出版面函数 `(t) → 每个字母的仿射`，两场共用。

**R3 交接物 = 一个几何原语 + 运动**：点 / 线 / 缝 / 描边 / 矩形，带屏幕位置、尺寸、速度、滚转角。上一场最后一拍把世界收成它，下一场从它展开。每个切点加测试：切点前后各一帧，交接物投影位置误差 ≤ 2 px、尺寸误差 ≤ 2%。

**R4 切点前最后一拍**：细分加速（8 分 → 16 分）、最后 0.1 s 镜头定住、交接物增益爬升到白热；每场规格里写明用哪几种。

**R5 歌词载体**：每句一个世界上的载体（路径、平面、刻字、实体），逐字母时刻、不早于书写头、白热冷却、长音变形；正对镜头的平面排版只留给打字/终端（Mono）这类机器的声音。

**R6 光标接力**：clay 光标在每一场都是书写头，并且是交接物；S10–S12 补上。

**R7 三次 COMMIT 逐次升级**（尺度递进：纸 → 栈 → 世界）：
- 第 1 级 S08：干净的字体标本。每个唱词一次全屏砸，COM 在第一个音节，MIT 砸下时 clay 漫满；一个副本；震 7 px；退场收成一条哈希细线。
- 第 2 级 S13：反色（ink 字 clay 底）+ 复制：每次 commit 变成 git log 里新的一层实体，按拍重砸（照 hook4 的 retrig）、描边回声；震 13 px；退场是 log 列变栈井。
- 第 3 级 S17：世界尺度：COMMIT 由设备墙上所有屏幕拼成，每块屏一个像素；MIT 砸下时整面墙同时亮；砸完之后全片唯一的一次完全静止（一拍），再进入「Pull request」。
