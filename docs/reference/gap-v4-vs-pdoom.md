# v4 和 pdoom 的差距分析

C 2026-10-01 写，依据：pdoom 源码（`reference/pdoom/`，和 GitHub 上 mexicat/pdoom-video 同一 commit `bdbad53`）、pdoom 的 TREATMENT、整片预览 v4、我们的源码。下面的数字都是对源码的直接统计。

## 量化对比

| 项目 | pdoom | clawd-mv v4 |
|---|---|---|
| 场景代码 | 19,602 行 / 17 个场景模块 | 6,212 行 / 18 场 |
| 时间线 | 22 个条目，平均约 7 秒，每个条目内部 3–6 个阶段 | 80 个镜头，平均 2 秒，多数镜头只有一个想法 |
| 自定义着色器（FSPass / ShaderMaterial） | 62 处 | 23 处 |
| GPU 线条（LineBatch，发光细线） | 25 处 | 2 处 |
| 粒子 / 火花 | 36 处 | 5 处 |
| 光线步进（raymarch）场景 | 4 个（shoggoth、paperclips、ilya、spacetime 透镜） | 0 |
| bloom（发光） | 绝大多数场 0.6–0.85，只让橙色发光 | 大多数场 0（视觉规范 v2 的海报后期关掉了 bloom / halation / 色散 / 暗角） |
| 返工 | 作者改到第 5 版 | 第 4 版，其中 v2/v3 主要是 Codex 做的 |

## 差距（按影响大小排序）

1. **媒介：我们是「被拍摄的海报」，pdoom 是「可以穿行的空间」。** pdoom 的镜头在真正的 3D 里移动：掉进等高线地形、冲进房间、穿过 Droste 递归。v4 的大部分动效是 `kit/lens.ts` 对一张平面图做推拉摇，没有视差、没有遮挡关系，本质是 Ken Burns。观众能感到「动了」，但感觉不到「进去了」。真正有 3D 的只有 S04、S07、S14（S15 是正交投影）。
2. **光：我们没有光。** pdoom 是近黑底上的发光细线、白热到冷却的字、只在橙色上的 bloom，画面有层次和体积。我们大面积纸色平涂、bloom 为 0，深度只能靠构图。这是「大制作感」最直接的来源，也是成本最低的差距。
3. **变形：pdoom 每场都是「A 变成 B」，我们多是「展示 A」。** loss 曲线变地形，蛇眼瞳孔匹配剪成 K 线，火花的线弯成回形针，帧变成递归。我们的日历城、玻璃板、骨牌、≤ 都是「一个东西在那里，被拍」。歌词里现成的比喻（shattering like glass、falling like rain）在我们片子里是两场并排的画面，在 pdoom 的做法里会是同一批碎片变成雨。
4. **贯穿全片的主线物件不够主动。** pdoom 的火花写第一句歌词、画 loss 曲线、变成 K 线、弯成回形针、最后变成导火索引爆，镜头一直跟着它。我们的光标在每场都在，但很少画东西、很少领镜头，所以场与场之间靠剪辑而不是靠一个物件连着。
5. **镜头太碎。** 80 个镜头平均 2 秒，每个镜头一个构图。pdoom 一个条目 7 秒，在里面按词和拍分阶段，有「推近 → 甩开 → 落定 → 再推」的完整句子。我们这一版在场内加了连续运动，但镜头本身还是短，很多运动来不及展开就被切掉。
6. **信息密度和冷幽默注释层。** pdoom 每帧都有三层：主体、仪表（坐标轴、读数、标签）、一两句面无表情的注释（`grokking (?)`、`sharp minimum (generalizes poorly)`）。我们画面留白很多，注释很少，所以「看第二遍还能发现新东西」的感觉弱。
7. **和音乐的咬合层次。** pdoom 用到底鼓、军鼓、踩镲、人声音高曲线（`fuse-pitch.ts` 让一根弦按真实唱的音高弯曲），切点前加速到十六分音符。我们主要是逐词和逐拍。
8. **工作量本身。** 代码量 3 倍、改了 5 版。前几版是 Codex 按图实现的，场景普遍只做到「还原了一张图」，没做到「一个连续的段落」。

## 不怀疑的部分

歌、逐拍网格和逐词对齐的精度、场景之间的几何交接、Archivo 连续轴 + Voice 的歌词形态、Clawd 的像素形象、整片的节奏骨架。这些已经是 pdoom 的水准或接近。

## 关于 P02 样片为什么失败（自我检讨）

P02 试图同时做第 1、3、5 条，但执行上把画面做暗、做空、做急了：读代码那段 1.9 秒塞进一次大变形，字被甩过去看不清，日历板又丢掉了 v2 分镜稿的版画质感。失败的是执行和取舍，「数据变成世界」这个方向本身不一定错。下一步如果要做，应当在 v2 构图和质感不变的前提下，一场一场往里加。

## 建议的升级顺序（性价比从高到低）

| | 做什么 | 范围 | 预计 |
|---|---|---|---|
| A | **光和材质**：INK 场景打开 bloom，只让 clay 发光；线条改成 GPU 发光细线；纸面加纤维、油墨压印、轻微色散；字刚写出时白热再冷却 | 全片，主要改 `kit/ground.ts` 和后期参数 | 1 天 |
| B | **光标升级为火花**：发光的点 + 拖尾 + 火星；每场由它画出关键几何（第 32 天的线路、≤ 的剪断、git 主干、骨牌的弧线），镜头跟它 | 全片母题 | 1–2 天 |
| C | **3–4 个招牌场改成真 3D 穿行**：S04 镜头从街道穿到 32 号塔脚下；S10→S11 玻璃碎片变成雨（同一批几何）；S15 ≤ 改成透视实体、镜头绕它走；S17 镜头穿过设备墙 | 4 场 | 每场 1 天 |
| D | **合并碎镜头**：同一场里相邻的短镜头合并成连续段落，场内用阶段代替硬切 | `shots.json` + 各场 | 随 C 一起做 |
| E | **注释层**：每场一两句冷幽默的 mono 注释和一个小仪表 | 全片 | 半天 |

建议先做 A + B（全片受益、风险低、不改构图），出一版整片给 Tim 看；再按 Tim 的意见挑 C 里的场做。

## 第二轮（2026-10-02）：对照 pdoom 的真实渲染帧

证据：pdoom 仓库里带着 14 张真实渲染帧（`reference/pdoom/app/plates/fig01–14.jpg`，片尾倒带用的缩略图）。和 v4b 每场中点的帧并排：`out/compare/pdoom-vs-v4b.png`。

亮度统计（灰度 0–1，每张缩到 480×270 后统计，取平均）：

| | 平均亮度 | 最暗 2% | 最亮 2% | 近黑像素（<0.08） | 近白像素（>0.85） | 饱和度 |
|---|---|---|---|---|---|---|
| pdoom | 0.26 | 0.07 | 0.73 | **45%** | 13% | 0.22 |
| v4b | 0.55 | 0.27 | 0.85 | **0%** | 36% | 0.31 |

结论（按影响排序）：
1. **明暗结构是最大的差距。** pdoom 近一半画面是黑的，光从黑里出来，所以发光、景深、雾都看得见。我们的「墨」是 `#1B2A4A`（中等亮度的蓝），没有一个像素接近黑；纸面场景又占了很大比例。整片是「均匀照亮的印刷品」，不是「电影」。V4-A 加了发光，但在中灰蓝和纸面上，发光几乎显不出来。这来自视觉规范 v2（PAPER / INK / CLAY 三种平涂底色），是旧决策本身的上限。
2. **每一帧都是一个被照亮的 3D 物件，带材质。** 版画排线刻出的手、金属回形针、编织导火索、光子环、笔记本屏幕的光溢出。我们大多是平面卡片和字；3D 的几场（S04、S07、S14、S15）也是没有光照和材质的方块。
3. **字住在空间里。** SINGULARITY'S 绕着黑洞弯，ALL THE WAY 贴在栈块的透视面上，we lit the fuse 沿导火索走。我们的字大多正对镜头叠在画面上。
4. **纸面场景靠细节密度取胜。** pdoom 只有两张纸面（钞票、公文），但满是扭索纹、编号、表格字段、签名、印章。我们的纸面是瑞士海报：大字 + 大留白。大字是我们的长处，缺的是「文件本身的真实细节」。
5. **每场一种「仪器」和画法。** 版画、示波器、钞票、公文、蓝图、光线步进、纺织……我们的物件（日历、清单、键盘、测试、提交）题材更窄，但同样可以给每个物件一种画法和材质。
6. **过程。** 风格手册写死了规则（底色近黑、只有橙色发光、「不要 AI 味」清单），一场一场做透，改了 5 版，场景代码是我们的 3 倍、自定义着色器 62 处对 23 处。

**需要 Tim 决定的事（主动质疑旧决策）**：要缩小差距，必须改明暗结构——把「墨」压到接近黑、让光成为主角，纸面只留给本来就是文件的场景（issue 表单、清单、PR 审查）并把它们做密。这和 2026-09-28 Tim 说的「全黑背景很无聊」、和视觉规范 v2 的纸 / 墨 / 橙轮换都相冲突。我的判断：pdoom 的黑不无聊，是因为黑里有光、有景深、有材质；无聊的是「平涂的黑加少量元素」。建议先拿 3 场（S04、S10、S16）做夜景版样片，构图不动，Tim 看了再定全片要不要改。
