# pdoom 的源码技术拆解（为什么好看），以及我们差在哪里

C 2026-10-02 写。T 的要求：「从 pdoom 的源码角度去分析，而不是截个图看视觉效果」。本文只依据源码和统计。
统计脚本：`tools/pdoom_census.py`（对 `reference/pdoom/scenes/*.ts` 和我们的 `app/src/scenes/s*.ts`、`parts/s*.ts` 按场景合并后做正则计数）。

最后一行是关键：**pdoom 的 3D 感不是靠「three.js 摆模型 + 材质」得来的**。它用 three.js 主要当 WebGL 外壳，真正的 3D 来自四种自写的做法（见第 2 节）。我们一直在 Canvas2D 里画平面图，再给少数场景放几个方块网格，两边的差距在方法上，不在颜色上。

## 2. pdoom 的四种 3D 做法（都在源码里）

### 2.1 每场先定义一个「数学世界」，所有东西都向它查询
- `loss.ts`：地形是一个函数 `terrH(u, v)`，**JS 和 GLSL 各写一份完全相同的版本**（`TERRAIN_GLSL`）。GPU 用它在 640×720 的网格上位移顶点、算法线、画等高线；CPU 用同一个函数：
  - 火花沿峡谷中心线走（`cuF(v)`），落地点、螺旋落进极小值，都由它算出；
  - 等高线标签用牛顿迭代吸附到等高线上（`onContour`），「local min.」是在 `terrH` 上做梯度下降找到的（`buildLabels`）；
  - 镜头不会钻进地面：每帧查 `terrH` 把相机抬到地面以上 1.4（`camera()` 末尾）。
  - 图表的 y 轴（对数 loss）和地形高度共用一个比例 `DEC`，所以「图表变成地形」在数学上是同一个坐标系。
- `paperclips-geo.ts`：回形针是一条按弧长参数化的中心线（A→R1→B→R2→C→R3→D），CPU 的火花路径、相机取景和 GPU 的 SDF 用同一份几何。
- `room-geo.ts`：图书馆过道按米建模，门、桌、书架都是坐标。
- `spacetime-lens.ts`：黑洞是一条物理公式 `β = θ(1 − θE²/|θ|²)`，每个像素反推回源平面去取格子和文字。
**我们**：场景是矩形、方块、文字框的排版，没有一个可以被查询的「世界函数」，所以镜头、字、Clawd、光标只能各自摆放，无法「互相知道」。

### 2.2 四种渲染方式（按用到的场景）
| 方式 | 怎么做 | 场景 |
|---|---|---|
| A. 位移网格 + 逐像素制图着色 | 高精度平面网格，顶点着色器用世界函数抬高；片元着色器用 `fwidth` 画等宽等高线、Tanaka 明暗（按坡向调线的亮度）、沿坡度画晕滃线、雾、揭幕前沿、冲击波纹、按拍沿等高线下行的脉冲 | loss |
| B. 全屏光线步进（SDF） | 片元着色器里从相机发射光线，步进 48–160 次求交；算法线、环境光遮蔽（AO）、软阴影、面光源辐照度、雾和体积光；shoggoth 还做了半分辨率 G-buffer（MRT）再按深度上采样 | paperclips、shoggoth、ilya |
| C. 自写投影 + 2D 抗锯齿细线 | 自己算相机基向量（R/U/F）做透视投影，近裁剪面裁线段，按深度淡出，再用 `LineBatch` 画成 2D 发光细线；`planeAffine` 把 Canvas 文字仿射贴到 3D 平面上；一场用到 13–34 万条线段 | room（四个线段批次 130k/90k/70k/50k）、stack、leftturn |
| D. 图像空间的物理 | 引力透镜、Droste 对数极坐标递归、带多重采样运动模糊的 2D 相机（梯形透视） | spacetime、loom、leftturn |

### 2.3 光照最后变成「线的疏密」
这是 pdoom 质感的核心：先正经算光（`dot(N, L)`、高光、AO、阴影、fresnel 轮廓光），然后**把明暗换算成雕刻线的覆盖率**（`paperclips-glsl.ts` 的 `shadeWireL`：`cov = hatchW(u, pow(tone,1.5)*1.15, fw)`；shoggoth 的排线沿管子的弧长方向走）。所以画面看起来是版画，但形体、体积、光源方向都是真的。
**我们**：S04、S14 有排线，但排线密度是写死的常量（`darkness = mix(0.30, 0.52, xSide)`），不随光照变化，所以只是「有纹理的方块」，没有体积。

### 2.4 字长在几何上，而且逐字计算
- loss 的峡谷歌词（`drawCanyonText`）：每个字形按弧长放在 3D 中心线上，宽度用相邻两点投影后的屏幕长度（透视压缩），高度用透视尺度，角度跟中心线切线；每个字有自己的出现时刻（按字符在词里的位置插值），出现时从压扁弹起，颜色从白热冷却。
- 「drop」四个字母竖着沿悬崖往下排，每个字母的位置取自火花在那个时刻的下落位置（`sparkPos(tg)`），越往下越大。
- room：歌词翻牌用 `planeAffine` 贴在 3D 翻牌板上，跟着板一起翻转。
- spacetime：歌词被黑洞真实地透镜弯曲，内圈还有翻转的虚像。
**我们**：绝大多数歌词是正对镜头的 Canvas 文字（`drawSet`、`gridSnap`），S14 的 `WordPlane` 是唯一贴在 3D 平面上的。

### 2.5 镜头是带物理的分段函数
loss 的 `camera(t)` 分 5 段，每段用 `orbit(target, yaw, pitch, dist)`，段与段之间用不同的缓动混合；目标点跟火花（坠落时用 `lerp3` 追）；加了地面碰撞、震屏（3 个冲击点 + 末段张力）、横滚 180°、末段 fov 从 34 拉到 64。火花坠落是真的匀加速（`gFall` 由落地时刻反算）。
**我们**：v4 的镜头大多是 `kit/lens.ts` 对平面图推拉（2D 变换），没有视差、遮挡和透视变化。

## 3. 结论：差距在哪一层

1. **方法层（最大）**：pdoom 每场先有一个数学世界，再用 A/B/C/D 中的一种方式把它渲染成「有体积的版画」，字和镜头都长在这个世界上。我们是「排版 + 动效」。换颜色、加发光、加镜头推拉都在排版层上修补，所以 T 看不出本质变化。
2. **着色层**：光照 → 线密度的转换我们完全没有。
3. **字的层**：缺少「字沿 3D 路径逐字排布」和「Canvas 贴 3D 平面」两种工具。
4. **密度层**：每场被逐词驱动的元素少一半以上，缓动少 4 倍，代码少 3 倍。

## 4. 我们要补的工具（先做工具，再用工具重做场景）

| 工具 | 来源 | 用途 |
|---|---|---|
| `kit/proj3d.ts`：相机基向量、投影、近裁剪、`seg3` 画进 2D 细线批、按深度淡出、`planeAffine`（Canvas 贴 3D 平面） | room.ts 790–845 行 | 线框 / 细线 3D 世界：栈、调用链、git 图、过道、设备墙 |
| `kit/heightfield.ts`：JS + GLSL 双写的高度函数、高精度位移网格、等高线 / Tanaka / 晕滃线着色、揭幕前沿、拍点脉冲 | loss.ts 21–161 行 | 「数据变成地形」：测试曲线、代码、日历 |
| `kit/raymarch.ts`：全屏 SDF 步进骨架（相机光线、法线、AO、软阴影、雾、超采样抽头）+ `engraveShade(tone, u)` | paperclips-glsl、ilya-glsl、shoggoth-glsl | 实体雕塑和空间：≤、32 号楼、键帽、玻璃 |
| `kit/pathtext.ts`：沿 3D 折线逐字排布、透视缩放、切线旋转、白热冷却、逐字出现时刻 | loss.ts `drawCanyonText`、`drawChartText` | 歌词骑在几何上 |

## 5. 建议的验证顺序

先做工具（约 2–3 天），然后拿**一场**按 pdoom 的完整方法重做，给 T 判断方法对不对，再铺开：
- 首选 **S15（≤ 雕塑）**：v2 分镜图本来就是「巨大的 3D 实体雕塑，密排斜向雕刻线，下横杠是一块长石条」，正好对应「光线步进 + 光照转线密度」；构图不变，镜头真正绕着它转，「Less / than / or / equal」刻在三个面上，Snip 时下横杠被剪断并真实下落。
- 备选 **S09（示波器 → 测试曲线地形）**：最接近 loss 的结构（一条曲线 → 一个世界）。
